# Changelog

## 0.4.64

- Исправлено преждевременное завершение полного сбора через рабочую копию вкладки: последняя отрисованная в момент запуска реплика больше не считается концом всей переписки без подтверждения физического конца. Автоматический режим сначала проверяет нижнюю границу снимка, затем отправляется к началу и только после этого собирает сообщения вниз.
- Неподвижное виртуализованное окно больше не считается подтверждённым началом только из-за повторяющейся сигнатуры. Для автоматического сбора требуется видимый первый turn, ручное подтверждение или реально наблюдавшееся движение вверх с последующей стабилизацией.
- Прокрутка через debugger/резервный путь сообщает о фактическом перемещении и отклоняет ложный успешный результат, когда чат не сдвинулся и физическая граница не подтверждена. Исправлена подмена scrollTop=0 значением window.scrollY.
- Перед окончательным сохранением проверяются обе независимые границы. Рабочий процесс по отметкам не выполняет автоматического поиска вверх или вниз до старта; если оба отмеченных края действительно видимы одновременно, даже очень короткий чат допустим без прокрутки.
- Ручные отметки учитывают контекст предыдущих реплик и различают действительно устойчивые DOM ID от слабых виртуальных идентификаторов.
- Старые архивы полного сбора, у которых нет записанного доказательства прохода, остаются доступными без удаления, но помечаются как «Полнота не подтверждена». Для новых успешных сборов сохраняются свидетельства начала и конца. Добавлены поведенческие тесты для коротких и длинных переписок.
- Интеграция с установленным Chrome и Google Docs остаётся предметом живой проверки, а не доказанной успешности по CI.

## 0.4.63

- Автоматическое объединение требует общего устойчивого ID сообщения: одинаковые длинные тексты с неустойчивыми ID больше не служат доказательством одной хронологической последовательности.
- Полная загрузка черновиков и поиск перекрытий вынесены из GET_STATE в отдельную кнопку «Показать черновики». Сохранённые архивы и Google Docs больше не ждут тяжёлой сверки при обычном открытии popup.
- Счётчики карточек черновиков теперь отражают полное проверенное объединённое окно, включая изображения, а не только один технический проход.
- При явном объединении копия пересобирается из актуальных источников. Более новая сохранённая контрольная точка имеет приоритет для изменённых подготовленных изображений. Оригиналы не удаляются.
- Дополнены поведенческие и исходные тесты. Сквозная проверка в установленном Chrome остаётся обязательной.

## 0.4.62

- Добавлен отдельный проверяемый модуль `lib/draft-overlap.mjs` для хронологического перекрытия черновиков со сдвинутыми началами. Поддерживаются вложенные, суффиксно-префиксные и цепочечные перекрытия.
- Сопоставление требует той же переписки по URL-идентификатору, нижней границы и диапазона. Совпадающее название не является ключом. Проверяются порядок, минимум две реплики, уникальная позиция и устойчивый ID или два содержательных текстовых совпадения.
- Повторяющиеся короткие реплики, разные устойчивые ID, конфликты текста и неоднозначные позиции останавливают объединение без потери данных.
- Объединённая версия сохраняется как отдельный `verified-merge:...` черновик с перечислением исходных ID; оригиналы остаются неизменными. Прогресс восстановления использует крайнюю подтверждённую хронологическую точку.
- Карточки незавершённых проходов группируются по проверенному перекрытию, включая случаи, когда третий черновик связывает два ранее раздельных.
- Просмотр, копирование, сверка, экспорт в Google Docs и продолжение незавершённой части теперь материализуют общую проверенную последовательность по явному действию пользователя.
- В пакет расширения включены ранее пропущенные `unfinished.html`, `unfinished.js`, `unfinished.css`, необходимые для просмотра незавершённого архива.
- Добавлены настоящие Node.js-тесты поведения сопоставления, повторов и большого диапазона. Проверка установленного расширения и полноты конкретного длинного чата в Chrome ещё необходима.

## 0.4.61

- Удаление незавершённого сбора ограничено точными ID черновиков, показанными в выбранной карточке. Широкий ключ переписки больше не захватывает соседние группы с отличающимся содержимым.
- Перед удалением проверяется, что состав выбранных черновиков не изменился и все они принадлежат одному базовому диапазону. При расхождении удаление прекращается.
- Сверка совместимых версий больше не уничтожает исходные черновики автоматически. Новая объединённая версия сохраняет provenance, а исходники остаются доступны для проверки.
- Быстрая библиотека показывает архивы, найденные в индексе/ссылках, даже если их нет в старом реестре метаданных. Для отсутствующих данных отображается ожидание вместо нулей.
- Загрузка подробностей обращается только к архивам с отсутствующими счётчиками/карточками, заполняет лёгкий реестр и не десериализует остальные завершённые сохранения.
- Дополнены автоматические регрессионные guards. Проверка поведения удаления и производительности на реальных архивах в Chrome остаётся обязательной.

## 0.4.60

- Исправлено зависание popup после уже завершённого сбора при открытии локальных архивов для экспорта в Google Docs.
- Библиотека сохранений загружается отдельным быстрым запросом из лёгкого реестра, без десериализации сообщений каждого архива.
- При сохранении архива в реестр записываются счётчики сообщений и изображений. Для старых сохранений без счётчиков показывается «…», пока фоновый запрос не подтянет данные; ложное значение 0 не подставляется.
- Тяжёлая загрузка статистики старых архивов перенесена на независимый этап, не блокирующий появление списка и кнопок экспорта.
- Просмотр состояния больше не запускает объединение и удаление технических черновиков и повторную регистрацию архива при каждом открытии.
- Автоматические проверки ограничены программным контуром; реальную задержку в Chrome нужно проверить после обновления.

## 0.4.59

- Исправлено продолжение ранее собранного основного архива по ручным границам: миграция наследованной метки `isFragment` выполняется до проверки режима продолжения.
- Исправлена очистка старого префикса «Фрагмент —» в заголовке мигрируемого основного архива.
- Выбранный локальный архив больше не заслоняет другой чат в popup: явный выбор применим только к текущему идентификатору переписки.
- При завершении слияния частичного и полного проходов выбирается фактический итоговый ID архива.
- Экспорт в Google Docs проверяет наличие конца текстового содержимого в документе после вставки и до отметки об успешном сохранении. В случае неподтверждённой вставки документ остаётся открытым, привязка и статус сохранения не обновляются.
- Добавлены статические регрессионные проверки. Фактическая вставка/разметка Google Docs требует проверки в Chrome.
- Черновики одного ручного сбора больше не разделяются только из-за смены технического режима `fragment` → `resume-draft`: идентификатор группы определяется исходной перепиской, границами и подтверждённой последовательностью сообщений.
- Версии черновиков с расходящимся содержимым сохраняются отдельными карточками; совпадающее название переписки не используется для объединения.


## 0.4.58

- Исправлена ошибочная классификация основного архива, собранного по ручным отметкам, как «фрагмента». Границы служат способом сбора полного архива, а не его отдельным видом.
- Новый основной архив получает обычный `lastArchiveId`, индекс переписки и доступ к продолжению, просмотру и сохранению в Google Docs. Исходные отметки остаются в `manualRangeMarkers`.
- Уже собранные в 0.4.56/0.4.57 архивы с ошибочным признаком фрагмента переводятся в основной архив без повторного сбора и без удаления сообщений; сохраняются ID и локальные данные.
- Восстановлена обычная маршрутизация экспорта: новый Google Doc, связанный документ, разбиение на вкладки/части и выбор завершённого архива.
- Убраны неверные надписи «фрагмент» в основном сценарии сбора; добавлены проверки классификации и миграции.
- Проверка фактической вставки в Google Docs на пользовательском Chrome отдельно обязательна.

## 0.4.57

- Восстановлен прямой просмотр любого сохранённого архива из библиотеки через «Просмотр и вкладки»: планировщик открывает точный archiveId, независимо от открытого ChatGPT-чата.
- Основная карточка архива явно показывает «Просмотр архива и вкладки», не скрывая прежнюю возможность разметить сообщения и экспортировать их по вкладкам Google Docs.
- Выбор архива в библиотеке отделён от основного lastArchiveId; GET_STATE показывает явно выбранный архив, а завершение нового сбора выбирает его для просмотра.
- Ручной диапазон принудительно выполняется в позиционированной текущей вкладке и исключён из старого автоматического восстановления, включая оставшиеся alarms предыдущих запусков.
- Продолжение черновика ручного диапазона использует сохранённый хронологический стык, а не режим повторного подъёма к началу.
- При восстановлении ручной диапазон сохраняет isFragment, обе отметки и отдельный fragmentLatestId; основной архив чата не подменяется.
- Ручной черновик без подтверждённой хронологической контрольной точки не объединяется автоматически: требуется новый запуск от отмеченного начала, данные черновика сохраняются.
- Добавлены исходные регрессионные guards для маршрута просмотра, вкладок, ручного диапазона и восстановления. Проверка в установленном Chrome остаётся отдельным обязательным этапом.

## 0.4.56

- Основной сбор упрощён до ручного диапазона: пользователь отмечает конец, затем начало и запускает сбор с видимого начала.
- Ручной диапазон всегда собирается в текущей вкладке; фоновая копия из основного сценария убрана, чтобы не терять вручную выбранную позицию.
- Для ручного диапазона обязательны обе границы — начало и конец.
- Перед сбором Архиватор больше не ищет «настоящий верх», не идёт сначала к нижней границе и не выполняет навигационный проход вверх.
- Ручной диапазон собирается одним хронологическим проходом только вниз до отмеченного конца.
- Navigation reconciliation для ручного диапазона удалён: итог строится из одного доказуемого прохода и затем режется точно по двум маркерам.
- Автоматический Retry/load-error recovery в ручном диапазоне отключён: Архиватор больше не ищет и не нажимает «Попробовать снова» во время этого сценария.
- Основной UX теперь: «Разметить диапазон» → «Собрать отмеченный диапазон» → «Сбросить отметки». Кнопка «Я в начале» и выбор фоновой вкладки скрыты из основного пути.
- Старые режимы продолжения, сверки и восстановления архивов сохранены отдельно и не определяют механику нового ручного диапазона.

## 0.4.55

- Исправлен ложный load-error recovery, при котором Архиватор мог считать `Retry / Попробовать снова` видимой кнопкой, хотя пользователь её не видел.
- Retry теперь считается доступной только если реально пересекает viewport, не скрыта через `aria-hidden/inert/opacity/pointer-events`, проходит hit-test через `elementFromPoint` и находится в локальном видимом контейнере с текстом ошибки загрузки.
- Перед сообщением «нажимаю Попробовать снова» кнопка повторно проверяется после короткой стабилизации DOM; stale-контролы виртуализированного интерфейса больше не запускают recovery.
- Та же строгая проверка добавлена в worker для прогрева фоновой вкладки.
- Исправление 0.4.54 по проверке реального движения debugger-wheel и fallback живого ChatGPT scroller сохранено.

## 0.4.54

- Возвращена историческая проверка реального движения ChatGPT после debugger-wheel из commit `23d1f2ab`.
- Успешный `Input.dispatchMouseEvent` больше не считается успешной прокруткой сам по себе: worker сравнивает `scrollTop` до и после wheel.

## 0.4.18

- Полный сбор снова двухпроходный: при движении вверх Архиватор реально собирает сообщения, а не использует проход только как навигацию.
- Обратный проход идёт от начала к зафиксированному концу, повторно собирает сообщения, сверяет покрытие с первым проходом и добирает реплики, которые выпали только в одном из проходов.
- Возвращена явная проверка количества: интерфейс показывает число сообщений первого и второго проходов и статус «совпало / не совпало»; несовпадение не замалчивается, а проходит через доказательную сверку.

- Продолжение незавершённого прохода использует ориентированный поиск по знакомым/незнакомым участкам: незнакомый участок ищет сохранённую часть, знакомый ведёт к сохранённому фронтиру, перескок фронтира разворачивает поиск и уменьшает шаг.
- Поиск продолжения больше не должен останавливаться после нескольких неудачных окон; при исчерпании одного направления проверяется противоположное.

- Кнопка остановки теперь сначала переводит job в терминальное состояние, поэтому физическая прокрутка прекращается сразу; сохранённая точка остаётся только для явного ручного продолжения.
- Ошибка до подтверждённого запуска больше не считается незавершённым сбором: бесполезная рабочая копия закрывается, recovery не создаётся.
- Добавлены статические regression-guards на двухпроходный контракт, сравнение количества, последовательный image hydration, pause/resume без скрытой навигации и lifecycle остановки.
